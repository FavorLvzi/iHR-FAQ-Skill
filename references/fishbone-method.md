# 鱼骨图排查法（本 skill 独有方法论）

用于回答"**某功能用不了 / 操作被拦 / 报错**"类问题（如打不了卡、流程发起失败、app 异常）。**不依赖 API 溯源**，凭用户反馈 + 功能机制常识即可系统定位。

> 与数据溯源（#91/#110/#96）的区别：数据溯源回答"**记录为什么不对**"；鱼骨图排查回答"**功能为什么用不了**"——后者发生在操作动作之前或之外，往往查不到记录/日志。

## 一、方法：鱼骨图结构

以问题为**鱼头**，从几大**原因类别**（鱼骨刺）逐类排查，每类下列具体**因子**。

```
        手机定位          打卡方式          打卡范围配置         系统规则
        ├─精确位置未开      ├─只配WiFi未配GPS   ├─围栏半径过小       ├─定位误差容忍值小
        ├─定位权限拒绝      └─楼下没连WiFi      ├─中心点坐标偏       └─打卡时间范围限制
        └─GPS冷启动漂移                        └─只覆盖楼内
        └───────────────────────────────────────────────────────────────┴ 问题（鱼头）
```

## 二、核心原则

1. **排查顺序 = 从用户自查到系统配置**：用户能自己动手的先查（手机设置/操作习惯），后台配置的后查（管理员操作）。先让用户排除自己侧，再反馈管理员。
2. **个性化定制**：用户自查步骤要**按设备/机型定制**，不甩通用清单。如 iPhone 重点查「精确位置」开关、安卓查应用权限。
3. **按概率排序**：鱼刺内因子按出现概率从高到低，回答时先说最可能的原因。
4. **分视角**：员工视角引导"自查手机→反馈HR"；管理员视角引导"查后台配置"。

## 三、典型应用

1. **打卡前异常·不在打卡范围**（有入口打不了）：四大类（手机定位/打卡方式/打卡范围配置/系统规则）+ 个性化手机排查。见 `attendance-field-logic.md` 三·八 C 路径鱼骨图①
2. **打卡前异常·没有打卡入口**（刚入职员工）：五大类——**APP应用配置（★最先查）**/登录入口侧（★试用企业错登、三方集成未配置）/入职状态/考勤配置/客户端。见 `attendance-field-logic.md` 三·八 C 路径鱼骨图②

## 四、推广：任何"功能用不了"类问题

当客户/员工反馈"XX 用不了"时，按鱼骨图结构回答：
1. 先问清**现象发生在操作前还是后**（决定走规则排查还是数据溯源）
2. 拆出**可能原因类别**（通常：设备/客户端 → 账号/权限 → 功能配置 → 系统规则）
3. 每类列**具体因子**，按概率排序
4. 按"用户自查 → 管理员配置"顺序排查
5. 给**兜底方案**（如补卡/重新提交/联系管理员）

> 注意：鱼骨图排查法产出的是**排查方向与引导**，实际修改配置是管理员在系统内的操作，AI 只指导不代改。
