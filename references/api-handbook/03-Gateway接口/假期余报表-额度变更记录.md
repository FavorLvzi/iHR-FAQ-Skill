# 假期余报表 · 额度变更记录（二方接口）★核心★

> 接口编号：#116（03-Gateway接口 扩展）  
> 端点：`GET /web/gateway/attendance/api/limitBill/record`  
> Host：`https://v5.ihr360.com`  
> 完整 URL：`https://v5.ihr360.com/web/gateway/attendance/api/limitBill/record?staffId={staffId}&vacationId={vacationId}&page=0&size=10`  
> 鉴权：宿主 AI 环境 `Authorization: Bearer ${IHR360_API_TOKEN}`（环境变量自动注入，Base URL `v5.ihr360.com`）｜前端插件 Cookie+XSRF  
> 状态：✅ 已实测（2026-08-04，年假 3 条流水）

---

## 描述

查询某员工某假期的**额度变更流水**（发放/结转/调整）。**问题2 核心接口**——补齐"非年假假期发放额度"缺口，可还原完整计算链（发放 → 使用 → 余额）。

---

## 请求参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| staffId | query | String | 是 | 员工 ID |
| vacationId | query | String | 是 | 假期类型 ID（如年假 `985d4ada...`） |
| page | query | int | 否 | 页码（从 0 起） |
| size | query | int | 否 | 每页条数（如 10） |
| r_id | query | String | 是 | 租户/路由标识 |
| u_id | query | String | 是 | 用户标识 |

## 请求示例

```
GET /web/gateway/attendance/api/limitBill/record?staffId=81f9eea8-aca4-465a-9d8b-aa72daf69b21&page=0&size=10&vacationId=985d4ada4ea944efbc10f0e7740e745f&r_id=u5q0ldzd4w5w3dt6&u_id=992311676526956544
```

## 响应数据

`data.content[]` 每项 = 一条额度操作流水：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 流水 ID |
| operateTime | String | 操作时间（yyyy-MM-dd HH:mm） |
| **operateReason** | String | **操作原因（自然语言，含额度来源说明）** |
| **operateLimit** | String | **操作额度（带符号+单位，如 "+5.0天"）** |
| carryoverTime | String | 结转时间 |
| expirationTime | Long | 有效期/过期时间（毫秒时间戳） |
| adjustResetInvalidStatus | String | 调整重置失效状态 |
| dataId | String | 关联数据 ID |
| cycleDateTime | String | 周期时间 |

## 对问题2 的价值（核心）

- **补齐"发放额度"缺口**：非年假假期也能通过本接口拿到额度变更流水（发放/结转/调整），`operateLimit` 带符号+单位
- **还原完整计算链**：额度流水（本接口）+ 使用明细（record/list #115 或 OpenAPI #77）+ 当前余额（OpenAPI #80/#82）→ 发放 − 使用 = 余额，可验证
- **配合**：#113 `limitBill/leaveSettingType`（哪些类型有额度单）→ 本接口逐类型查流水
- 实测年假 3 条：2025周期+5天 → 2026周期+5天 → 结转+5天（有效期 2026-08-19）→ 与 OpenAPI #82 年假余额 5 天可交叉印证（5+5+5-已用=余额）
- 接口能力已验证：按员工+假期查询可返回该员工的完整额度流水（发放/结转/作废逐条可见）；批量场景可遍历员工与假期类型全量拉取（参数精简：staffId+page+size+vacationId 即可）

## 参数名变体

- **当前已验证**：`vacationId`（用于假期余报表等后端，200 OK，6 条数据）
- **另一变体**（用户在"假期详情"页抓包看到，URL 形如 `record?id={vacationId}&u_id=...`）：参数名 `id`，但实测脚本调 `id` 报 500 错误——**后端是否真的接受 `id` 待确认**，或需要额外的 cookies/headers。脚本默认用 `vacationId`

## r_id 校验实测（2026-08-04）

**r_id（第三个 id）后端不校验**，四组对照全部 200 OK（total=6）：

| 场景 | r_id 值 | 结果 |
|------|---------|------|
| 省略 r_id | — | ✅ 200 |
| 抓包真实值 | u5q0ldzd4w5w3dt6 | ✅ 200 |
| 乱填值 | aaaaaaaaaaaaaaaa | ✅ 200 |
| 另一会话值 | xjpcoi48yg7x8olq | ✅ 200 |

**结论**：`r_id`/`u_id` 为前端路由标识（埋点/日志用途），后端不参与鉴权校验，可省略。

**必需参数仅 2 个**：
- `staffId`（员工 ID，来源：OpenAPI #1/#28 员工接口或 #5 花名册搜索）
- `vacationId`（假期类型 ID，来源：OpenAPI **#79** 全部 21 种）

**"查所有员工变更流水"拼接**：`limitBill/record?staffId={员工}&vacationId={假期}&page=0&size=100`，双层循环即可全量拉取。
