## 描述

**「累计转薪资结余记录」表格**——记录加班转薪资额度的每一次变更（含薪资锁定/取消锁定、加班单变更、调休过期转薪资）。**问题3 核心数据源**：能回答"转薪资额度何时、为何、变化多少"。

## 表格列（已确认）

| dataindex | 标题 | 含义 |
|-----------|------|------|
| changeTime | 变更时间 | 变更发生时间 |
| **changeReasonType** | 变更原因类型 | 枚举见下 |
| overtimeType | 类型 | NORMAL 工作日 / WEEKEND 休息日 / STATUTORY 节假日加班 |
| **deltaAmount** | 变更额度 | 本次变化量（带符号） |
| **originalAmount** | 原额度 | 变更前额度 |
| **changedAmount** | 变更后额度 | 变更后额度 |
| changeDetail | 变更明细 | 详细说明 |

## changeReasonType 枚举（★ 核心）

| 值 | 中文 | 业务含义 |
|----|------|---------|
| **SALARY_PLAN_CHANGE** | **薪资方案考勤取数** | **= 薪资锁定/取消锁定转薪资额度**（考勤引用薪资方案时取数） |
| **OVERTIME_FORM_CHANGE** | **加班单变更** | 加班单增删改/重算导致转薪资额度变化 |
| **ADJUST_EXPIRED_TRANSFER** | **调休过期转薪资** | 调休额度过期自动转薪资 |

## 对问题3 的价值（核心）

- **补齐"薪资锁定"数据缺口**：用户业务认知 = "只有薪资模块锁定转薪资额度后才会真正使用；考勤引用取消锁定则返还额度"。本表格的 `SALARY_PLAN_CHANGE`（薪资方案考勤取数）即该动作的日志！
- **完整额度变化链**：deltaAmount（变化量）+ originalAmount（原额）+ changedAmount（变后额）→ 逐笔还原
- **三类变更全覆盖**：锁定/解锁（SALARY_PLAN_CHANGE）+ 加班单变更（OVERTIME_FORM_CHANGE）+ 调休过期转薪资（ADJUST_EXPIRED_TRANSFER）
- 与 #86 `salaryUsedOvertimeHour`（薪资已用终值）配合：本表看"动作"，#86 看"状态"

## 数据接口（✅ 已实测 2026-08-05）

**端点**：`POST /web/gateway/attendance/api/overtimeMonthlyAccount/pageSalaryTransferChangeRecord`  
**参数**：分页 + 查询条件（请求体待精确确认，可查 staffId / 时间范围等）  
**响应 data.content[]** 每项：

| 字段 | 说明 |
|------|------|
| staffId | 员工 ID |
| changeTime | 变更时间（yyyy-MM-dd HH:mm:ss） |
| changeReasonType / Name | 变更原因类型 / 中文名（SALARY_PLAN_CHANGE 薪资方案考勤取数 等） |
| overtimeType / Name | 加班类型 / 中文名（NORMAL 工作日加班 等） |
| amountUnit | 单位（HOUR） |
| **originalAmount / changedAmount / deltaAmount** | 原额度 / 变更后额度 / 变更额度（带符号） |
| **changeDetail** | 变更明细（自然语言，含方案名与月份，如"薪资「测试薪资方案」-2026年01月锁定1.00小时"） |
| affectedFormIds | 影响单据 ID 列表 |

### 实测样例（2026-08-05，14 条全为 SALARY_PLAN_CHANGE）

- `薪资「工资薪金正式方案」-2026年01月锁定1.00小时` → original 1.0 → changed 0.0 → **delta -1.0**
- `薪资「测试薪资方案」-2026年01月解锁1.00小时` → original 0.0 → changed 1.0 → **delta +1.0**
- `薪资「测试薪资方案」-2025年11月解锁5.00小时` → original 1.0 → changed 6.0 → **delta +5.0**

### 锁定/解锁方向规则（★ 已实证）

- **锁定**（考勤被薪资方案引用取数）→ `deltaAmount` 为负，可用转薪资额度减少
- **解锁**（考勤引用取消）→ `deltaAmount` 为正，额度返还
- 与用户业务认知完全一致："只有薪资模块锁定后额度才真正被使用；取消锁定则返还"
