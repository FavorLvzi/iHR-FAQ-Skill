# 审批类型分组-列表（二方，问题5 定位链路第 1 层）

## 基本信息

| 项目 | 内容 |
|------|------|
| 接口名称 | 审批类型分组选择器（列表） |
| 接口地址 | `GET /gateway/workflow/aggregate/activiti/common/approvalGroup/selector` |
| 请求方式 | GET |
| 鉴权方式 | Cookie+XSRF（前端插件）/ 宿主 AI 环境 `Authorization: Bearer {IHR360_API_TOKEN}` |
| Host | `v5.ihr360.com` |
| 实测时间 | 2026-08-07（用户抓包） |

> 返回**审批类型分组**列表（系统分组 + 自定义分组）——问题5"流程走向分析"定位审批类型的**第 1 层入口**：分组 →（下一步）审批类型列表 → approvalSettingId → `approval/setting/draft/{id}` 流程定义。

## 响应结构

| 字段 | 类型 | 说明 |
|------|------|------|
| code | Number | 0=成功 |
| data | Array | 分组列表 |
| id | String | 分组ID（UUID，如 `bb57a414-...`） |
| groupName | String | 分组名（系统分组：人事相关/考勤假期/薪资福利/招聘相关/默认分组；自定义分组：GROUP_CUSTOM） |
| seqNo | Integer | 排序号 |
| groupType | String | 分组类型：`GROUP_SYSTEM` 系统分组 / `GROUP_CUSTOM` 自定义分组 |

## 实测样例（脱敏）

```
0: 人事相关   (系统分组, seqNo=1)
1: 新招聘     (GROUP_CUSTOM, seqNo=2)
2: 考勤假期   (系统分组, seqNo=3)   ← 补卡/请假/加班/外出 在此分组
3: 薪资福利   (系统分组, seqNo=4)
4~N: 自定义分组（项目1部/项目2部/学习/默认分组 等）
```

> 备注：请假流程定义 `basicSettingVo.groupId`（如 `d9131e67-...`）即对应该接口返回的分组 `id`——可按 groupName 反查分组归属。

## 定位链路（问题5 前置，★三层全通 2026-08-07）

```
① approvalGroup/selector → 分组列表（本接口，✅已实测）
   （或直接调 findApprovalGroupVo 一步拿到分组+类型全量，更推荐）
   ↓
② 审批设置-分组及类型列表（findApprovalGroupVo）→ approvalSettingId  ← ✅已实测（见 审批设置-分组及类型列表.md）
   ↓
③ approval/setting/draft/{approvalSettingId} → 流程定义（✅已实测）
```

> **★已收口（2026-08-07）**：本接口可被 `findApprovalGroupVo` 替代（后者一步返回分组+全部审批类型及三件套 ID）；用户抓包 `GET /gateway/workflow/aggregate/approval/setting/findApprovalGroupVo` 拿到补卡 approvalSettingId=`b69494b9-...`，交叉验证（请假 formId 一致）确认列表 id 即 draft 路径参数。
