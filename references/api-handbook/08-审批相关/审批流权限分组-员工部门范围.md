# 审批流权限分组-员工部门范围（OpenAPI，员工分组查询 ★缺口已补）

## 基本信息

| 项目 | 内容 |
|------|------|
| 接口编号 | （OpenAPI 新增） |
| 接口名称 | 获取审批流权限分组信息及成员管理部门id范围 |
| 接口地址 | `POST https://openapi.ihr360.com/openapi/thirdparty/api/auth/v1/group/approval?departmentStatus=ENABLE` |
| 请求方式 | POST |
| 鉴权方式 | Bearer（OAuth access_token，**OpenAPI 全通**） |
| 实测时间 | 2026-08-10 |

> **★员工分组查询接口（问题5"员工→适配流程"的缺口零件）**：返回当前公司**审批流权限分组**（如 CEO审批流/分公司CEO审批流/部门经理审批流）+ 每组下**员工名单** + **该员工管理部门 id 范围**。未分配员工的管理部门则默认管理所有部门。

## 请求参数

| 参数 | 类型 | 位置 | 必填 | 备注 |
|------|------|------|------|------|
| departmentStatus | String | Query | 否 | `ALL` 全部（含停用部门）/ `ENABLE` 启用（默认） |
| page | int | Body | 是 | **从 0 开始** |
| size | int | Body | 是 | **最多 10 条/页**（超 10 按 10） |

### 请求示例

```json
POST /openapi/thirdparty/api/auth/v1/group/approval?departmentStatus=ENABLE
{"page": 0, "size": 10}
```

## 响应结构

| 参数 | 类型 | 父节点 | 说明 |
|------|------|--------|------|
| code | int | Body | - |
| data | PageData | Body | - |
| totalPages | long | data | 总页数 |
| totalElements | long | data | 总数据量 |
| content | List&lt;AuthGroupVo&gt; | data | 分组列表 |
| groupId | String | content | 分组ID |
| groupName | String | content | **分组名称（即流程条件里的"员工分组"，如 CEO审批流）** |
| staffDepartments | List&lt;StaffDepartmentVo&gt; | content | 员工与部门关系 |
| staffId | String | staffDepartments | 员工ID |
| staffName | String | staffDepartments | 员工姓名 |
| departmentIds | List&lt;Long&gt; | staffDepartments | 该员工管理部门 id 范围（空=默认管理所有部门） |

> **staffDepartments 长度为 0** = 该分组下没有员工。

## 实测样例（2026-08-10，脱敏）

```
CEO审批流        → 员工A（管理部门=[0,7,22,25,28,31,...] 全公司）
部门经理审批流    → 员工B/员工C/员工D/员工E/员工F/员工H（各管 1 个部门）
分公司CEO审批流   → 员工X（管 5 个部门）、员工D（管 5 个部门）
```

## ★ 与流程定义条件的对应关系（关键）

补卡流程 6 分支条件里的"**发起人所在员工分组包含 X**"（condActivitiType=INITIATE_STAFF + nodeUserSettings 人员列表）——**该接口即 X 的查询来源**：

| 补卡条件分支 | 审批流权限分组（本接口实测） | 命中员工 |
|------------|---------------------------|---------|
| 条件1: 员工分组包含 CEO审批流 → 发起人自己(APPLICANT) | CEO审批流 | 员工A |
| 条件2: 员工分组包含 分公司CEO审批流 → 会签指定职位CEO | 分公司CEO审批流 | 员工X/员工D |
| 条件4: 员工分组包含 部门经理审批流 → 会签员工分组 | 部门经理审批流 | 员工B~F/H |

> **AI 使用路径（员工→适配流程）**：
> 1. `auth/v1/group/approval` 拉全部分组 → 建 **staffId → [分组名]** 映射
> 2. 目标员工不在任何分组 → 走流程定义**默认分支**（flowType=OTHER）；在分组 → 按 flowPriority 匹配对应条件分支
> 3. 结合 #2 员工详情（部门/职位）可继续匹配"发起人部门包含 X"、"发起人职位包含 X"类条件
> 4. 完整输出：该员工发起某审批 → 命中哪条分支 → 走到哪个审批人
