## 接口 #28：批量获取员工企业内任职记录

获取员工在企业内的任职记录，包括主岗与兼岗。

> ⚠️ **请求体格式**：**对象包裹**，非纯数组。使用 `{"staffIds": [...]}` 格式。
> ⚠️ **数量限制**：最多 **100 个**员工 UUID。

### 端点

```
POST /openapi/thirdparty/api/staff/v1/employmentRecords
```

### 鉴权方式

| 方式 | 说明 |
|------|------|
| Headers | `Authorization: Bearer {accessToken}` |
| Headers | `Content-Type: application/json` |

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `staffIds` | String[] | 是 | 员工 UUID 数组，≤100 个 |

### 示例请求体

```json
{
  "staffIds": [
    "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
    "b2c3d4e5-f6a7-8901-bcde-f12345678901"
  ]
}
```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `staffId` | String | 员工 UUID |
| `staffName` | String | 员工姓名 |
| `departmentId` | String | 部门ID |
| `departmentName` | String | 部门名称 |
| `positionId` | String | 岗位ID |
| `positionName` | String | 岗位名称 |
| `jobTitleId` | String | 职务ID |
| `jobTitleName` | String | 职务名称 |
| `positionGradeId` | String | 职级ID |
| `positionGradeName` | String | 职级名称 |
| `employBeginDate` | String | 任职开始日期，`yyyy-MM-dd` |
| `employEndDate` | String | 任职结束日期，`yyyy-MM-dd` |
| `employType` | Integer | 任职类型：`1`（主岗）、`2`（兼岗） |
| `source` | Integer | 数据来源：`1`（手动）、`2`（系统） |
| `operatorId` | String | 操作人ID |
| `operatorName` | String | 操作人姓名 |

### 示例请求

```bash
curl -X POST "https://openapi.ihr360.com/openapi/thirdparty/api/staff/v1/employmentRecords" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..." \
  -H "Content-Type: application/json" \
  -d '{"staffIds": ["a1b2c3d4-e5f6-7890-abcd-ef1234567890"]}'
```

### 示例响应

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "staffId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "staffName": "张三",
      "departmentId": "dept-uuid-001",
      "departmentName": "技术部",
      "positionId": "pos-uuid-001",
      "positionName": "高级开发工程师",
      "jobTitleId": "title-uuid-001",
      "jobTitleName": "高级工程师",
      "positionGradeId": "grade-uuid-001",
      "positionGradeName": "P7",
      "employBeginDate": "2024-03-01",
      "employEndDate": null,
      "employType": 1,
      "source": 2,
      "operatorId": "op-uuid-001",
      "operatorName": "系统"
    }
  ]
}
```

## 接口 #30：获取工作经历清单

批量获取员工的外部工作经历（入职当前公司之前的工作经历）。

> ⚠️ **纯数组请求体**：直接传入员工 UUID 数组，无需对象包裹。

### 端点

```
POST /openapi/thirdparty/api/staff/v1/experiences
```

### 鉴权方式

| 方式 | 说明 |
|------|------|
| Headers | `Authorization: Bearer {accessToken}` |
| Headers | `Content-Type: application/json` |

### 请求体

```json
["uuid1", "uuid2"]
```

### 响应字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `companyName` | String | 公司名称 |
| `jobTitle` | String | 职位名称 |
| `jobDescription` | String | 工作描述 |
| `enrollDate` | String | 入职日期，`yyyy-MM-dd` |
| `quitDate` | String | 离职日期，`yyyy-MM-dd` |
| `flexAttributes` | Map | 自定义字段（扩展属性） |

### 与 #28 的区别

| 对比项 | #28 企业内任职记录 | #30 工作经历 |
|--------|-------------------|-------------|

## 接口 #33：获取员工直属上级清单

> ⚠️ **对象包裹请求体**：使用 `{"staffIds": [...], "reportToType": "..."}` 格式。

| 方式 | 说明 |
|------|------|
| Headers | `Authorization: Bearer {accessToken}` |
| Headers | `Content-Type: application/json` |

### 请求体

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `staffIds` | String[] | 是 | 员工 UUID 数组 |
| `reportToType` | String | 是 | 汇报类型：`Enum.Administration`（行政）、`Enum.Business`（业务）、`Enum.Finance`（财务） |

## 接口 #36：获取员工自定义信息子集记录

获取员工自定义信息子集的记录数据。子集结构完全由元数据定义（见 #37），响应为动态 Map。

> ⚠️ **混合参数传递**：`metaCode` 通过 Query 参数传递，`staffIds` 通过 Body（纯数组）传递。
> ⚠️ 响应为 **完全动态的 `List<Map<String,Object>>`**，字段名由元数据定义决定。

### 端点

```
POST /openapi/thirdparty/api/staff/v1/subset
```

### 鉴权方式

| 方式 | 说明 |
|------|------|
| Headers | `Authorization: Bearer {accessToken}` |
| Headers | `Content-Type: application/json` |

### 请求参数

**Query 参数：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `metaCode` | String | 是 | 子集元数据编码 |

**Body（纯数组）：**

```json
["uuid1", "uuid2"]
```

### 响应说明

响应为 `List<Map<String,Object>>`，每个 Map 代表一条子集记录。字段名遵循以下命名规范：

| 字段类型 | 字段名示例 | 说明 |
|---------|-----------|------|
| 字符串 | `D_STRING_0`, `D_STRING_1` | 文本字段 |
| 日期 | `D_DATE_0`, `D_DATE_1` | 日期字段 |
| 整数 | `D_INTEGER_0`, `D_INTEGER_1` | 整数字段 |
| 浮点 | `D_DOUBLE_0`, `D_DOUBLE_1` | 浮点数字段 |
| 布尔 | `D_BOOLEAN_0` | 布尔字段 |
| 时间 | `D_TIME_0` | 时间字段 |
| 日期时间 | `D_DATETIME_0` | 日期时间字段 |
| 枚举 | `D_CODE_TYPE_0` | 编码类型字段 |
| 长文本 | `D_LONG_STRING_0` | 长文本字段 |
| 部门 | `D_DEPARTMENT_0` | 部门字段 |

### 示例请求

```bash
curl -X POST "https://openapi.ihr360.com/openapi/thirdparty/api/staff/v1/subset?metaCode=emergency_contact" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..." \
  -H "Content-Type: application/json" \
  -d '["a1b2c3d4-e5f6-7890-abcd-ef1234567890"]'
```

### 示例响应

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "staffId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "D_STRING_0": "张三(父)",
      "D_STRING_1": "父亲",
      "D_STRING_2": "138****8888",
      "D_INTEGER_0": 1
    },
    {
      "staffId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "D_STRING_0": "李四(母)",
```

## 接口 #37：获取子集元数据定义

获取自定义信息子集的元数据定义，用于解析 #36 接口返回的动态字段。

### 端点

```
GET /openapi/thirdparty/api/staff/v1/subset/metadata
```

### 鉴权方式

| 方式 | 说明 |
|------|------|
| Headers | `Authorization: Bearer {accessToken}` |

### 请求参数

无。

### 响应结构

```
Map<String, List<FieldMeta>>
```

以 `metaCode` 为键，每个元数据包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `columnName` | String | 字段编码（如 `D_STRING_0`） |
| `displayName` | String | 字段显示名称 |
| `fieldType` | String | 字段类型，共 10 种（见下方） |
| `required` | Boolean | 是否必填 |
| `valid` | Boolean | 是否启用 |
| `codeType` | String | 编码类型（当 `fieldType=CODE_TYPE` 时） |

### fieldType 枚举（10 种）

| 值 | 说明 |
|----|------|
| `BOOLEAN` | 布尔 |
| `INTEGER` | 整数 |
| `DOUBLE` | 浮点数 |
| `DATE` | 日期 |
| `TIME` | 时间 |
| `DATETIME` | 日期时间 |
| `CODE_TYPE` | 编码（下拉选择），需配合 `codeType` 解析 |
| `STRING` | 短文本 |
| `LONG_STRING` | 长文本 |
| `DEPARTMENT` | 部门 |

### #36 与 #37 的配合使用流程

```
步骤 1: 调用 #37 获取元数据定义
       ↓
步骤 2: 根据 metaCode 获取字段列表（columnName + displayName + fieldType）
       ↓
步骤 3: 调用 #36 传入对应 metaCode 获取数据
       ↓
步骤 4: 使用元数据定义解析动态字段（如 D_STRING_0 → "紧急联系人姓名"）
```

### 示例请求

```bash
curl -X GET "https://openapi.ihr360.com/openapi/thirdparty/api/staff/v1/subset/metadata" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiJ9..."
```

### 示例响应
