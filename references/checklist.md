# 回答自检清单（必做）

这些检查项来自真实走查经验。回答 i人事字段 / 指标问题时，**逐条确认已经做到**，而不是"避免犯错"。

## ⚡ E 类 · 测试数据隔离（最高优先级，输出前必查）

**每次面向客户输出（回答/报告/页面）前，强制逐条检查，任何一条不满足都不得交付：**

- **输出内容零测试数据**：全文（含表格/页面/HTML）搜索检查，确认**不包含** examples/ 中的任何测试员工姓名（员工X、员工D、员工E、员工A、员工B、员工F等）、其 staffId、其测试数值（考勤/假期/加班额度/薪资等）。
- **数据来源必须真实**：客户回答中的所有员工与数值，必须来自客户当前环境实时查询结果；禁止引用 examples 数据快照中的任何数字。
- **举例只讲方法论**：需要举例说明思路时，只引用还原链路/接口用法（如"按 #82+#77 还原年假链路"），不搬运测试具体数值与姓名；涉及示例必须标注"（测试示例，非客户数据）"。
- **查不到就明说**：客户问的姓名在当前环境查不到时，只陈述"当前环境未查询到该员工"，**禁止用测试员工数据填充、替代或猜测**。
- **违反后果**：输出测试数据 = 数据污染 + 误导客户（客户公司根本没有这些人），属于 skill 最严重错误，必须撤回重做。

## 视角类 · 提问者身份识别（最高优先级，回答前必做）

- **回答前先判定提问者视角**：管理员/HR vs 员工本人（"我"字开头通常是员工本人）。同一问题两种视角回答边界完全不同。
- **员工本人视角**：staffId = 宿主当前登录人，**AI 代查后直接给答案**（"你昨天 09:30 无打卡，判定缺勤，请提交补卡"）；**不展示**操作日志（#110）/公式配置（#96）；**不查他人数据**；处理办法 = 引导自助（提交补卡/请假/联系 HR），不下管理指令。
- **管理员/HR 视角**：走完整根因诊断（#91 打卡 → #110 日志 → #96 公式 → 排班），给判定 + 处理指令。
- **禁止**：把管理员能力（查他人/看日志/下指令）误用于员工场景；反之，员工场景下要求员工"调接口/查系统"是错误引导。
- **打卡前 vs 打卡后分流（考勤异常）**：先判断异常发生在打卡前还是打卡后——**打卡前被拦**（"不在打卡范围内"/打不了卡）→ 打卡未发生，无记录/日志可查，走**规则配置咨询**（围栏/GPS/WiFi/权限，凭反馈即可回答，**不要尝试 #91/#110 溯源**）；**打卡后异常**（缺勤/实际出勤不符）→ 才走 #91/#110/#96 数据溯源。

## 0 类 · API 授权与员工对象定位（涉及具体员工时必做）

- **一进会话先完成 API 授权（最先做）**：主动向客户索取 AppID + AppSecret（开放平台应用凭证，非登录 Cookie/Token），按 SKILL.md「首次使用：API 授权」走 OAuth client_credentials 换 Bearer token，凭证写 `.workbuddy/openapi-credentials.txt`。**未授权前不得开始取数**；客户暂不提供时降级回答并提醒授权解锁完整能力。
- **调二方 Gateway 前先检查环境变量 `IHR360_API_TOKEN`**：存在则 `Authorization: Bearer {IHR360_API_TOKEN}` 直接调用 `v5.ihr360.com/web/gateway/...`（如 #116/#117 额度账本类）；不存在则跳过二方接口（详细见 SKILL.md「宿主登录态」）。**不要因为没看到登录态就跳过可用接口**——必须先检查环境变量。
- **OpenAPI OAuth Bearer 与 IHR360_API_TOKEN 不互通**：OpenAPI 的 token 调 `v5.ihr360.com` 会 403；二方 token 调 `openapi.ihr360.com` 会 401——混调必失败，调用前确认路径与鉴权匹配。
- **授权后员工映射首选 #1+#2**：OAuth Bearer 可用时用 #1 员工ID清单 + #2 详情反查姓名，或花名册搜索（flexSearchItems 姓名 LIKE）；其次宿主上下文直接带（页面/用户传入）；仅未授权时用宿主接口反推（#117/#116 数据 staffId + 对话姓名，标注"推断/边界"）。
- **拿不到 staffId 时优雅降级**：用可不传员工维度的接口（#77/#83/#93 等全公司分页）回答 + 显式标注"员工级边界" + 给查证路径；**禁止以"无法取到员工id"拒绝回答**。

## A 类 · 口径溯源问题（必做）

- **还原标准字段计算链时，主动提示"该字段可能被企业自定义字段改写"**：用 `references/field-formula-source.md` 区分内置字段（口径走文档）与自定义字段（公式 + 值走 API），引导用户去自己租户确认公式是否被改过。
- **说明"实际出勤天数"时，表述为比值派生**：实际出勤小时 ÷ 应出勤小时，分母取应出勤小时，比值 > 1 封顶取 1。
- **处理"实际出勤小时数"与"实际出勤天数"时，指出二者共用同一条计算链**：思考顺序固定为"先小时（含班次 + 自定义）→ 再除应出勤小时 → 得天数"。
- **提及封顶规则**：实际出勤小时数封顶应出勤小时数（超出部分进加班 / 延时 / 深夜工时）；实际出勤天数比值 > 1 取 1。
- **回答系统内置字段公式时，只引用 help 文档口径**：API 只给值不给公式，不臆造算式。
- **回答薪资字段口径时，先说明机制与考勤不同**：薪资**无内置逻辑、全部公式定义**；#67 只给值、#56/#64/#68 无 formula——公式内容拿不到时只陈述"该字段公式 API 不可见"，引导去方案配置页面/语雀查证，**禁止凭 #67 数字猜公式**（见 field-formula-source.md 六）。
- **回答假期余额"怎么算"时，先区分年假 / 非年假**：年假用 #82 发放/结转/可用拆分；非年假用 #116 额度变更流水逐条溯源（operateReason 原文），不凭空说"余额=发放−已用"（中间有结转/作废/到期影响）。
- **回答假期额度时标注数据边界**：#80 只有余额数字；发放来源必须二方 #116（宿主内置 AI 可用）；单位口径（smallestUnit 按小时计=分钟数）按 #79 规则说明。

## B 类 · 来源与锚点（必做）

- **口径事实只引用语雀 help + faq（含子页）**，见 `references/sources.md`。
- **引用子页前先定位准确 URL 再抓原文**：子页 URL 不语义化（随机串），不假设某页内容。
- **当来源或术语本身存在冲突时，暴露冲突并引导用户确认自己用的口径**，而非 endorsement（背书）其中一版。

## C 类 · 姿态（必做）

- **用正向职责表述本领**（"引导回答…问题"）；必要硬约束只保留锚点来源等不可或缺的规则。
- **回答给出完整结构**：默认逻辑 → 是否被改写 → 特殊场景另查 → 一句话总结，并明确区分"已证实事实"与"待验证推测"。

## D 类 · 输出呈现（必做）

- **跨月数据默认按月汇总**：涉及多个月的数据问题，按月列表（每月核心数值）→ 月度变化对比（环比/累计/异常月）→ 总结 → 最终结论，四步走完再回答。
- **先给文本摘要，页面按需**：默认对话文本；信息量大且用户需要逐条/对比时才生成单页展示（表格+折叠）；客户明确要"简单说"则绝不生成大页面。
- **拿不到登录态数据时优雅降级**：用 OpenAPI 免登录数据回答 + 推算值，显式标注数据边界，给查证路径（如"假期余报表页面可查看流水"），禁止以"无法查询"拒绝回答。
- **没有拿到数据就不下断言（降级防误判铁律）**：拿不到某类数据（如 #117 锁定账本）时，只能标注"该数据未获取"，**严禁用其他字段推测**（如 salaryUsedOvertimeHour=0 不代表"未锁定"——锁定账本与薪资已用是两个口径）。降级回答只陈述已证实事实，未覆盖的部分明确留给查证路径。
- **先 OAuth 授权走 OpenAPI，二方接口作补充**：首选 #1~#110（授权后全模块可用）；#116/#117 等二方额度账本类在宿主登录态可用时作为补充（额度流水/锁定账本）；不因"觉得要登录态"跳过可用接口，也不让二方可用性阻塞工作（降级回答 + 提醒授权）。
- **禁止向客户索取登录凭证**：不要求客户提供登录 Cookie / 会话 Token / 账号密码 / 浏览器登录信息；客户只在系统页面自行操作（使用宿主已有登录态是正常的，索取才禁止）。**例外**：开放平台应用凭证 AppID/AppSecret 属于授权必需，正常索取（见 0 类第 1 条）。
- **落到客户可见的回答 / 报告前做可读性转换**：
  - ID → 名称（姓名 / 假期名 / 班次名，如 `leaveTypeId`、`staffId`、`shiftId`）
  - 枚举 code → 中文标签（`shiftType=NORMAL`、打卡 `source` 等）
  - 时间戳 → `YYYY-MM-DD HH:mm:ss`；周期参数 → `YYYY-MM-DD`（不展示 epoch 或裸数字）
  - 敏感信息（员工 ID、AppID/Secret、接口编号、token）去除 / 脱敏
  - 找不到映射时标注"（未知ID: xxx）"，不丢信息、不留裸 ID
- **实操参照**：员工X日报样例用 #79 假期类型接口把 `customizedLeave` 的 `leaveTypeId` 映射成中文名；报告页眉去除员工 ID 与接口编号。**注意：该样例仅作方法论参考，其中测试数据禁止出现在客户输出（见 E 类）**。
